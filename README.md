# PrepX
Online Examination &amp; Preparation website
<h2>🚧 Collaboration Guidelines</h2>

<h3>1️⃣ Create a Personal Branch</h3>
<ul>
  <li>🛑 Never work directly on the <code>main</code> branch.</li>
  <li> Create a new branch for every feature or fix.</li>
  <li>🧾 <strong>Branch naming convention:</strong><br>
<code>feature/&lt;your-github-username&gt;</code><br>
<em>Example:</em> <code>feature/visheshjha11</code><br>
📌 Use dashes <code>-</code> to separate words and keep the name short but meaningful.
</li>

</ul>

<h3>2️⃣ Do Not Push Directly to <code>main</code></h3>
<ul>
  <li>🔒 The <code>main</code> branch is protected.</li>
  <li> All code must go through a pull/merge request.</li>
</ul>

<h3>3️⃣ Pull Request (PR) Rules</h3>
<ul>
  <li>✅ Test your code before creating a PR.</li>
  <li> Ensure no linting or build errors.</li>
  <li> Write a clear title and description.</li>
  <li>🔗 Link related issues if applicable.</li>
</ul>

<h3>4️⃣ Code Review & Merging</h3>
<ul>
  <li> All PRs must be reviewed by at least one team member.</li>
  <li> <strong>Only <code>@visheshjha11</code> can merge into <code>main</code>.</strong></li>
</ul>

<h3>5️⃣ Stay Updated</h3>
<p>🔄 Regularly sync your branch with <code>main</code>:</p>
<pre><code>git checkout main
git pull origin main
git checkout your-branch
git merge main</code></pre>

<h3>6️⃣ Follow Coding Standards</h3>
<ul>
  <li> Use consistent formatting (e.g., Prettier, ESLint).</li>
  <li> Follow the project’s file and folder naming conventions.</li>
  <li> Use meaningful commit messages:</li>
</ul>

<pre><code>feat: add login functionality
fix: resolve session timeout issue</code></pre>

<h3>7️⃣ Issue Tracking</h3>
<ul>
  <li> Use GitHub Issues to track work.</li>
  <li> Assign issues to yourself when working on them.</li>
</ul>
